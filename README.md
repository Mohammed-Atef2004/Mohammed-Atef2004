## 🏛️ Engineering Principles I Follow

> The patterns I reach for daily — not because they're trendy, but because they hold up under real complexity.

| Principle | How I Apply It |
| --- | --- |
| **DDD with Rich Aggregates** | Behavior-first entities, encapsulated invariants, no anemic models. State changes only go through domain methods. |
| **Vertical Slice Architecture** | Each feature owns its full stack — Commands, Queries, DTOs, Mappings — keeping capabilities cohesive and avoiding horizontal coupling. |
| **CQRS with MediatR** | Strict command/query separation. Writes go through a transaction behavior; queries never open a transaction. |
| **Business Rules as First-Class Objects** | `IBusinessRule` implementations checked before any state mutation — failures modeled as typed `Result`, not exceptions. |
| **Domain Events After Commit** | Events collected by an EF Core `SaveChangesInterceptor` and dispatched via MediatR **only after** the transaction commits. Failed saves never trigger side effects. |
| **Architecture Tests** | NetArchTest enforces layer dependency rules in CI — Domain never references Infrastructure, aggregates stay sealed, handlers don't drift. |
| **Soft Delete & Audit as Cross-Cutting** | Global EF Core query filters + interceptors. Business logic never touches `IsDeleted` directly. |
